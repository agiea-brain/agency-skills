# Voice skill template

Open this at step 8. It is the shape of the skill this build produces. Fill every section from the counts, the diffs and the interview. Save it in the user's own skills folder under a name like `<their-name>-email`.

## Frontmatter

```yaml
---
name: <their-name>-email
description: Load whenever drafting an email for <name>: client updates, follow-ups, introductions, coaching, partner and vendor mail, or any message sent from their inbox. Not for posts or newsletters.
---
```

## Sections, in this order

### 1. Evidence base
One paragraph: how many sent emails and how many rewrites the skill is built on, the date range, and which source wins when they disagree.

### 2. Draft mechanics
Copy these in as written. They are the rules that stop a voice skill from doing damage:
- Drafts only, always. Never send, even when asked to "send them". The person sends everything themselves.
- A reply stays in its original thread, created as a reply to the message it answers.
- Editing a reply draft can detach it from its thread in some mail clients. After any edit, check the draft still sits in the thread. If it detached, delete it and recreate it as a reply.
- Never insert a link that is not on the verified-links list. Write `insert link here` instead.
- A link in the email signature is not a booking link unless the person says it is.
- Never say a file is attached unless it is. Write `[attach file here]`. A file the agent built and attached in the same step counts as verified.
- The verified-links list: each link, what it is for, and who it goes to.

### 3. Register map
A table with one row per register: who, median length, warmth, greeting, closer, exclamation range. Then the median length across all mail, and the share under 50 words. Pick the register before writing a word.

### 4. Mechanics of the page
Greeting, paragraph length, lists, bold, sign-off, closer lines in order of frequency, dashes, exclamation points. Each with its count.

### 5. Patterns
Numbered. Each pattern has:
- a name the person would recognise,
- the register it applies to,
- the count behind it (sent mail) or the rewrite it came from,
- one quoted line from their real mail.

Common pattern areas to check for: how they open after someone apologises, how they ask for things, how they give advice, how they say no, how they show proof, how they handle money, how they make and answer introductions, how they schedule.

### 6. Avoid list
Words, phrases and moves the person cuts, each with where it was seen. Include "over-polishing" if their real mail has typos and run-ons.

### 7. Examples
Three to five real emails, one per register, with names and private details changed if the skill will be shared. Under each: why it is a good example.

### 8. How to grow this skill
- Every rewrite: diff it, add the change to Patterns with its register, then log it.
- Every quarter: re-sweep 30 to 40 sent emails and correct any rule the counts no longer support.
- A rule from one email type stays scoped to that type until the sent mail shows it holds elsewhere.

### 9. Learning log
A table: date, source (rewrite or sweep), what changed in the skill.
